# TeachWell demo guide

Everything TeachWell does today, and step-by-step walkthroughs to try it with the fictional demo accounts. For setup, see the [README](../README.md).

## Feature reference

- Instructor/CTL dashboards, role switching and fictional module/page/assignment browsing.
- Tenant and course ACL checks on the server; neither reviewer nor admin role grants global course access.
- Course owners can share with an active CTL reviewer in their tenant and revoke access. Each actual change records the actor, target reviewer, course and UTC timestamp atomically.
- Optional Canvas PAT connect/replace, validate and disconnect, with AES-256-GCM token encryption, owner/tenant isolation, approved-host/public-IP safeguards and sanitized audit records. The UI never displays a saved PAT.
- Read-only listing/import of active teacher courses: paginated modules, pages, assignments and repeated module placements. Imported copies are private until shared. Refresh preserves local IDs/shares and earlier immutable snapshots; failed imports preserve the prior course copy.
- Versioned rubric library (CTL): draft, edit criteria and four rating anchors, publish. Published versions are immutable in EF and PostgreSQL.
- Element reviews of pages and assignments, pinned to an immutable content snapshot and rubric version. Ratings 0–3, N/A (excluded) and Not reviewed (reported as missing coverage, never zero). Deterministic checks propose findings from sanitized structural evidence (image alt text, headings, link text, table headers, assignment rubric, availability); reviewers confirm or reject each one before publishing. Owners see published reviews and confirmed findings only.
- Revision tasks built from one or more confirmed findings on one element, assigned automatically to the course owner. The documented status machine (Draft → NeedsRevision → InProgress → ReadyForReview → Resolved, with ChangesRequested, Blocked/Resume, Withdrawn and NotApplicable) is enforced server-side per actor, with required reasons where the workflow calls for one. A live snapshot comparison, a comment thread visible to both parties, and an append-only history are included. Fictional demo courses support a clearly labeled simulated content update standing in for a real Canvas edit, so the full review → task → fix → resolve loop can be exercised offline.
- Faculty Support Center: support tickets with a documented, no-dead-end status machine (New → Triaged → InProgress → WaitingOnInstructor → Resolved → Closed, reopenable from either terminal-looking state), triaged by any CTL reviewer in the tenant through a shared queue rather than per-course access. A ticket's optional link to a course/element/revision task shows real titles only to viewers who currently have access to that course; the ticket itself stays visible either way. CTL can assign tickets, attach a knowledge-article or workshop recommendation, and comment with the requester. An editable knowledge base (unlike rubrics and reviews, articles are not frozen once published) and a minimal workshop listing with capacity-aware waitlisting round it out. Closing a ticket never touches a linked revision task.
- Alignment and reporting: instructors add course competencies (one at a time, or by pasting a list of learning outcomes, for example from Simple Syllabus, then reviewing and approving them) and map them to assignments; a course alignment report identifies orphan competencies (no mapped evidence) and unmapped assignments (no competency). A course quality report averages rubric scores across published reviews and lists outstanding (unresolved) findings. A CTL-only overview aggregates every accessible course plus tenant-wide support themes. A personal revision-task report (with a CSV download) is scoped to whatever is yours. Every report states its scope, generation time and caveats; none shows a pass/fail or compliance badge.
- Configurable review standards (in progress, see [ADR 011](ADR-011-REVIEW-ENGINE-AND-IMPROVEMENT-GUIDE.md)): every automated check is a configurable rule. CTL reviewers maintain versioned **standard sets** that switch checks on or off, set their severity and word lists, and write the "why it matters / how to fix it / example" guidance instructors see under each finding. Each course uses the most specific published set for its department and delivery mode (which the CTL records on the course), falling back to a college-wide set. Published versions are immutable, every review records the version it started under, and a preview shows how a draft would change a course's findings before it is published. Thirty-eight checks cover accessibility, navigation, assessment, content and cognitive load (page and paragraph length, an English reading-level estimate, lists typed as plain text, colour-only instructions) and course design (module overviews and size, uneven workload, deadlines clustered on one day, vague or unassessed outcomes using Bloom's taxonomy, outcomes whose assessments sit below their level, and no low-stakes practice early in the course). The seeded college-wide v1 keeps the original 19; the extended demo data publishes v2 sets that adopt the rest.
- Course-level reviews: a CTL reviewer reviews a whole course's structure (module order and naming, starting point, unplaced or unpublished content, assignment due dates, competency alignment) against course-level rubric criteria. The review is pinned to an immutable snapshot of that structure, like page reviews. Course findings name the module or assignment they concern, link to it in Canvas, and become ordinary revision tasks. Design-consistency criteria stay reviewer-judged, supported by previews of every page captured with the structure.
- Formatted content: the course page shows each page, assignment, quiz and discussion with its Canvas formatting (headings, lists, tables, emphasis, alignment, and text and highlight colours mapped to a readable palette), with a Plain text switch.
- Visual page previews: each review shows the page's headings, lists, tables and emphasis as captured, with missing or file-name alt text and empty headings flagged in place. The preview is an allowlisted re-serialization: no scripts, styles, URLs or images are stored or rendered, and Canvas themes and media are not reproduced. See [course review and preview decisions](ADR-009-COURSE-REVIEW-AND-PREVIEW.md).
- Canvas course export import: instructors upload a course's `.imscc` export (Canvas → Settings → Export Course Content), no Canvas connection needed. `Start-Local.ps1` accepts exports up to 2 GB (`-MaxUploadMegabytes` sets a lower limit); elsewhere the API defaults to 500 MB unless `CourseExports__MaxUploadMegabytes` is set (maximum 2048); course files and media inside them are counted and skipped, so large media-heavy exports import quickly. Modules, pages, assignments (with points, due dates and rubric metadata), publish states and previews come in through the same pipeline as live imports. Uploading a newer export refreshes the course without rewriting reviewed content. Classic quizzes and surveys are imported with their settings and question text, and discussions with their prompts (graded ones count as assessments). External-tool assignments say which tool the work happens in. New Quizzes are recognised, but their questions live in Canvas's New Quizzes tool and are not in exports. Announcements, files and media are listed but not imported. The live Canvas connection reads quizzes (with questions) and discussions too. Built to Canvas's documented export layout, and verified by the project owner on October 22, 2026 by uploading a real export from the college's Canvas. See [export import decisions](ADR-010-COURSE-EXPORT-IMPORT.md).
- Readiness review and CTL endorsement: once the improvement guide's required steps are resolved or justified, the instructor asks the CTL for a readiness review. A reviewer takes it from the **Readiness** queue, which shares the course with them. They then request changes, or endorse the course after publishing a review. An endorsement is dated, names the standard-set version it was given against ("CTL-endorsed against … v2 on …"), never changes, and shows **re-check due** after `Readiness:ValidityMonths` (default 36) or when at least `Readiness:ChangeThresholdPercent` (default 25%) of the course's items change. Course cards show each course's readiness, and a notification bell tells instructors and CTL reviewers when a request is made, taken, withdrawn or decided (in-app only). Each standard-set version can require a course-level review, a number of item reviews and a rubric before endorsing. See [ADR 013](ADR-013-READINESS-REVIEW-AND-ENDORSEMENT.md).
- Oversight: CTL reviewers (**Oversight** tab) and a read-only **Academic administrator** (demo: Dana Brooks) see readiness states, the areas and issues where courses most need work, help requests from guide steps, weekly guide progress, a course table and endorsement history across the college, filterable by department. Figures describe courses, never people, and nothing opens course content without a share. Filter by department or program and download the course table as CSV. Courses are re-checked automatically every 24 hours (`Oversight__AutoRecheckHours`; 0 turns it off), and CTL reviewers can re-check every course at any time. The system administrator grants and revokes roles on **People and roles**, and reads the **Audit trail** (filter by action, person and date). See [ADR 014](ADR-014-OVERSIGHT-AND-ACADEMIC-ADMINISTRATOR.md).
- Glossary: terms an instructor may not know, such as Bloom's taxonomy, WCAG, UDL, cognitive load and orphan competencies, are underlined wherever they appear in guide guidance, recommendations and reports. Hover over or select one for a plain-language explanation, links to free reading (W3C, WebAIM, CAST and university teaching centres), and **From your CTL**. That opens **Glossary** (Help, in the sidebar) at the term, listing the CTL's knowledge articles and upcoming workshops on it, with **Ask the CTL about this**. The CTL lists an article under a term by tagging it with the term's name. CTL reviewers can also reword any term, add the college's own (with links) or hide one on the Glossary page; changes are audited and apply to everyone at the college. See [ADR 015](ADR-015-GLOSSARY.md).
- Start here: instructors see a four-step checklist on their dashboard: bring in your course, work through the improvement guide, ask for a readiness review, get endorsed. It is based on what they have actually done, with the next step highlighted and one button to take it. **Four tools, one goal** explains how TeachWell's tools fit together. Course pages open with the course's name, what TeachWell is looking at, and **On this page** links; the import panel numbers the Canvas export steps. Codes such as "ReadyForReview" appear as plain words ("Waiting for a CTL check"). See [ADR 016](ADR-016-PLAIN-LANGUAGE-AND-START-PATH.md).
- Typed React API client, loading/empty/error/authorization states, responsive UI, PostgreSQL migrations and idempotent seeds.

## Walkthroughs

Start the app with `scripts/Start-Local.ps1` and use the one-click demo accounts on the sign-in screen.

Try sharing Designing for Everyone with Jordan Lee, then sign in as the reviewer and choose CTL reviewer. Remove access as the instructor and refresh the reviewer workspace to see revocation take effect. Only the owner sees sharing controls. Content already viewed cannot be recalled.

Try a review: sign in as the reviewer, choose CTL reviewer, open Foundations of Web Development, start a review of the assignment, select **Run automated checks**, confirm or reject each proposal, rate a criterion and publish. Then sign in as the instructor to read the published review. The demo course contains deliberate, fictional accessibility issues for the checks to find. Scores describe one snapshot against one rubric version; they are not a compliance or accessibility certification. See [review decisions](ADR-005-REVIEW-FRAMEWORK.md).

Try a revision task from that same published review: select **Create a revision task from confirmed findings**, choose one, and create it. Assign it from the task screen, then sign in as the instructor to find it under the course's **Revision tasks** (or **Revision tasks** in the sidebar), start work, add a comment, and use the demo-only **Record simulated update** action to stand in for a real Canvas edit. Back as the reviewer, open the task to see the content comparison and resolve it. See [revision task decisions](ADR-006-REVISION-TASKS.md).

Try support: sign in as the instructor, open **Support**, and submit a ticket (or open a revision task and select **Request help with this task** to link it automatically). Sign in as the reviewer, choose CTL reviewer, open **Support → Triage queue** to find it even without owning or reviewing the related course, respond, recommend a job aid or workshop, and resolve/close it — the linked revision task's own status never changes. CTL can also author knowledge articles (**Knowledge base**) and schedule workshops (**Workshops**); published articles stay editable, unlike rubrics and reviews. See [faculty support decisions](ADR-007-FACULTY-SUPPORT.md).

Try importing a course export: sign in as the instructor, open **Import courses**, and upload `samples/fictional-course-export.imscc`, optionally with a made-up Canvas address such as `https://canvas.example.edu/courses/9876`. Share it with a CTL reviewer to review it, or try its course-level review.

Try a course-level review: sign in as reviewer2 (Morgan Blake) and open DATA 150. Open the published **Whole course** review to see the course outline: use **Preview** on any page, and read the findings about the empty, inconsistently named "Data storytelling" module. Or start your own from **Start course review** with the "Course-level design (demo)" rubric. Any page or assignment review now opens on a **Visual preview**, with **Plain text** one click away.

Try course standards: sign in as the reviewer, choose CTL reviewer, and open **Standards**. Open "College-wide course standards (demo)" version 1 (read-only), then create a new standard set for a department, turn a check off or change its severity and guidance, save, and **Run preview** against WEB 101 to see how the findings would change. Publish it, then open WEB 101 and use **Course standards** to set the course's department. New reviews of that course now use your set, and their findings show your guidance; reviews already started keep theirs. Signed in as the instructor, the same panel shows which standards apply and why, without edit controls. The extended demo data includes an Online set and classified courses. See [review engine decisions](ADR-011-REVIEW-ENGINE-AND-IMPROVEMENT-GUIDE.md).

Try alignment and reporting: sign in as the instructor, open a course, and under **Alignment and quality** add a competency and map it to an assignment — watch the coverage figure and the orphan/unmapped lists update. Open **Reports** in the sidebar to see your own revision tasks (with a CSV download). Sign in as the reviewer, choose CTL reviewer, open the same course to read the same report (no edit controls), then open **Reports** for the CTL-only overview across every course you can access, plus tenant-wide support themes. See [alignment and reporting decisions](ADR-008-ALIGNMENT-AND-REPORTING.md).

## Optional: live Canvas connection (personal access token)

Phase 2's connection, course import and sharing slices are implemented. Authorized live Canvas verification is still outstanding; automated Canvas responses are explicit test fixtures. The importer currently requires explicit active teacher enrollment and supports text from modules, pages and assignments; unsupported content is labeled, and larger courses may exceed the documented prototype limits.

To enable the connection workflow locally, use `./scripts/Start-Local.ps1 -CanvasHost 'your-approved-canvas-host.example.edu'` with an authorized hostname. The script protects the local encryption key using Windows DPAPI. See [Canvas connection setup](CANVAS_CONNECTIONS.md) for key management, API details and test boundaries. Starting without that option keeps Canvas disabled.

After saving a connection, select **List available courses**, then **Import course**. Open **Courses** to browse the local copy and its source links. Import the same course again to refresh it. See [import decisions and limits](ADR-004-CANVAS-COURSE-IMPORT.md). Imported pages keep their structural evidence and an allowlisted formatted preview, but not media or Canvas styling (see [ADR 005](ADR-005-REVIEW-FRAMEWORK.md) and [ADR 009](ADR-009-COURSE-REVIEW-AND-PREVIEW.md)); no automated compliance judgment is made.
